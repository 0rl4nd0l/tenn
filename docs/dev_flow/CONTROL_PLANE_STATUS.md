## Operator Interpretation

The Tenn control plane is mostly a repo-backed operator protocol: markdown skills, task cards, validation scripts, report bundles, and templates. Some checks are real code and some are automatic only if Codex loads repo hooks. Slash-goal behavior and the goal monitor are host-local Codex automation, not Tenn repo functionality.

For critical work, Orlando should force the repo-backed skill by path, require a task card, require check-diff/report validation, and require Runtime Functionality Proof before any runtime/product/data `DONE` claim.
