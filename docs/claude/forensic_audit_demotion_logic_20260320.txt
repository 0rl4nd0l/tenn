--- Key qualitative findings ---

Finding 1 [Confirmed]
  The non_canonical_scope + confidence 0.0 combination is the most ambiguous
  pattern. Many EVN rows with this combination have no competing canonical for
  the same metric/period. If confidence 0.0 is being assigned as a downstream
  consequence of scope classification (circular: "it's non-canonical, therefore
  0.0 confidence"), then rows are being systematically suppressed without
  independent value-quality evidence. Affects operating_cash_flow, ebitda, and
  revenue in mixed-layout documents.

Finding 2 [Confirmed]
  reconciliation_context (958 rows BHP, 33.5%) appears well-calibrated. Sampled
  rows show correct identification of reconciliation items ("Underlying EBIT,"
  "Loss from Discontinued operations," "Net debt at beginning of FY"). These rows
  are preserved in context.json. This category does not appear miscalibrated.

Finding 3 [Confirmed]
  pro_forma_context and missing_statement_period_end are correctly applied in
  all sampled rows. Not miscalibrated.

Finding 4 [Confirmed]
  canonical_conflict_same_period contains the highest-severity errors.
  Row B-3 (revenue 50% discrepancy) and D-1 (gross_profit 65x discrepancy) are
  both from this reason. Large-magnitude conflicts suggest conflict resolution is
  choosing between rows from different entities with incorrectly identical scope
  labels. This is not necessarily a demotion logic bug — it may be an upstream
  scope labeling bug surfacing as a conflict.

Finding 5 [Confirmed]
  metric_statement_mismatch is partially miscalibrated. Row C-1 shows a case
  where the metric value is correct and identical to canonical, but the source
  table was misclassified as income_statement when it is actually a balance sheet
  table embedded in an appendix. The mismatch is in the source classification,
  not in the metric-to-statement alignment.

Finding 6 [Confirmed]
  BHP v4 -> v12 pipeline change demoted rows that were previously canonical.
  v4 had 532 canonical rows; v12 has 161 (70% reduction). Row B-4 (ebit 25,906M
  was canonical in v4, demoted in v12) is the clearest regression candidate.
  However v12 values may be more accurate — old rows are not unconditionally
  trusted.

Finding 7 [Inferred]
  RIO orchestrator-layer demotions (collision_unit_evidence_rejected,
  lower_ranked_candidate) appear correctly applied in sampled rows.
  Negative orchestrator_unit_evidence_score values consistently correspond
  to rejected rows. No obvious false demotions in the RIO orchestrator layer.

Finding 8 [Confirmed]
  29M stress test old vs fresh runs are bit-identical (377 demoted rows each,
  identical distributions). Demotions are deterministic. Problems are structural
  in the logic, not stochastic.

periods. Large enough to suggest extraction quality differences. v4 rows are NOT

================================================================================
10. TOP SUSPECT DEMOTION RULES
================================================================================

Ordered by evidence strength:

--- 1. canonical_conflict_same_period (HIGH severity, moderate calibration risk) ---

Issue: Conflict resolution is selecting between rows that may not be truly
comparable (different entity scopes mislabeled as same scope). Large-magnitude
conflicts (50%, 65x) suggest upstream scope labeling errors are not being caught
before conflict resolution fires.

Effect: Wrong canonical row survives; legitimately better row is demoted.

Engineering target: The conflict resolution gate, not the demotion label itself.
Pre-condition check: are both conflicting rows truly from the same entity scope?

--- 2. metric_statement_mismatch (MEDIUM severity, partially miscalibrated) ---

Issue: Applied correctly when a metric genuinely appears in the wrong statement
type. Applied incorrectly when the statement family extractor mislabels an
appendix-embedded balance sheet table as income_statement.

Effect: Correct metric values with correct numeric content are demoted with a
misleading label. No data loss (values preserved in context.json), but the
mismatch label incorrectly implies the metric is untrustworthy.

Engineering target: Statement family classifier for appendix-embedded
multi-statement summaries.

--- 3. non_canonical_scope + confidence 0.0 interaction (MEDIUM severity, ambiguous) ---

Issue: In mixed-layout documents (EVN style), metrics from appendix/note contexts
consistently receive confidence 0.0 and non_canonical_scope. If no primary-statement
extraction exists for the same metric/period, these rows result in data gaps with
no canonical substitute.

Effect: Missing canonical metrics for entire periods in mixed-layout documents.

Engineering target: The confidence assignment logic for note-disclosure and
appendix-sourced rows. Determine whether confidence 0.0 is independently
evidence of extraction quality or is derived from scope classification
(which would create circular suppression).

================================================================================
11. RECOMMENDED NEXT ENGINEERING TARGET
================================================================================

DO NOT commit resources to a wholesale demotion logic rewrite.

Investigate in this order:

1. Statement family classifier for appendix-embedded tables
   Root cause of a significant fraction of metric_statement_mismatch false
   positives and the upstream cause of several canonical_conflict_same_period
   errors. A misclassified statement family contaminates both the demotion label
   and the conflict resolution pre-conditions.

2. Entity scope validation before canonical_conflict_same_period fires
   Add a pre-check: if two competing rows claim the same scope (consolidated_statement)
   but their values differ by more than a threshold (e.g., >20%), flag as a
   scope-label conflict before running conflict resolution. Do not silently pick
   a winner.

3. Confidence 0.0 diagnostic for non_canonical_scope rows
   Determine whether confidence 0.0 in these rows is independently derived from
   extraction quality evidence, or is set as a consequence of scope classification.
   If the latter, these rows need a separate quality signal before the scope rule
   suppresses them.
