# Sector Analysis Standard

## Scope and Trigger

Apply this standard for sector- or industry-level analysis requests where the user asks for broad peer or thematic assessment instead of a single-company thesis.

## Inputs and Evidence Contract

1. Keep sector-wide claims and company-specific claims clearly separated.
2. Use only current-turn evidence for factual comparisons.
3. Mark interpretation as interpretation, not confirmed fact.
4. Do not backfill missing peer metrics with assumptions.
5. Explicitly disclose gaps in peer coverage or stale inputs.

## Execution Steps

1. Scope Pass:
Name the sector scope and confirm what universe is actually covered.

2. Current State Pass:
Summarize confirmed current conditions and notable trend signals.

3. Relative Strength Pass:
Identify leaders/laggards only where direct evidence exists.

4. Risk and Counterpoint Pass:
Include disconfirming evidence and alternative interpretations.

5. Unknowns Pass:
State what data would change confidence materially.

## Output Contract

Use this top-level section order:

1. `Sector Scope:`
2. `Current State:`
3. `Relative Leaders and Laggards:`
4. `Risks and Counterpoints:`
5. `Unknowns:`

Every substantive factual line must include user-visible source grounding.

## Memory and Follow-up Rules

1. Sector outputs are analysis artifacts, not automatic memory writes.
2. If proposing memory capture, present it as optional and ask for confirmation.
3. Follow-up actions should be explicit and bounded (for example specific missing peers to pull).
