Stage 1: Discovery

Sources

ASX Announcements API (primary)
MarketIndex (fallback)
newspaper4k (54 AU sources)
Scrapling + Playwright (JS pages)

Data Collected

Ticker symbol
Announcement date
Source URL
Document title
doc_class, doc_subtype

Logic

Dedup by source_url (unique constraint)
Return only new_document_ids
Types: 4C, 4D, 4E, 5B, periodic, annual, continuous

Stage 2: Persistence

Target

PostgreSQL documents table
document_id: canonical UUID (v5 from source_url)
Status: DISCOVERED → DOWNLOADED → EXTRACTED

Key Fields

document_id (UUID)
ticker, source_url
doc_class, doc_subtype
published_at, ingested_at
pdf_path, pdf_sha256

Method

pipeline.insert_discovered_documents()
ON CONFLICT DO NOTHING
Returns list of new IDs only

Stage 3: PDF Download

Process

HTTP fetch of PDF URL
Validate content-type, size
Write to docs_root filesystem path
Compute SHA-256 fingerprint

Updates

document.pdf_path
document.pdf_sha256
document.status = DOWNLOADED

Method

pipeline.download_pdf_for_document()
Celery task: async in worker

Stage 4: Extraction Gate

SKIP (title match)

Substantial holder forms
Director/officer notices
Cessation of director notices
Market sensitive changes only

PROCESS (whitelist)

4C / 4D / 4E periodic reports
5B cash flow statements
Annual reports + IFRS full accounts
Half-year / quarter reports

Purpose

Prevent unnecessary LLM calls
announcement_importance.py classifier
Fail-fast for unextractable docs

Stage 5: Multipass Extraction

Pass 1
Structure Extraction
  • Sections (prose blocks)
  • Tables (row/col structure)
  • Metadata (title, date)
  • Method: Docling (default) / PyMuPDF
Pass 2
Metric Extraction (LLM)
  • revenue, ebit, np_attributable
  • fcf, total_equity, capex, net_debt
  • balance sheet items
  • cash flow components
  • Confidence scores per metric
Pass 3
Risk/Guidance (LLM)
  • risk_summary
  • risk_bullets
  • guidance_summary
  • material_changes
Safety: FX handling (denormalize non-AUD, mark fx_converted), confidence threshold gates, generalization requirement — must work across 4D/4E/5B/full IFRS from different companies and sectors.

Stage 6: Chunking

Method

chunk_prose_sections()
Split on logical section boundaries
Deterministic chunk_index (no randomness)

Output

List of (chunk_text, chunk_index) pairs
Chunk ID format: {document_id}:{chunk_index}

Invariant

NEVER use uuid4() for chunk IDs
IDs must be reproducible from same input

Stage 7: Embedding

Models

Sentence Transformers (CPU, in-process)
Ollama via API (optional, port 11434)
Model: nomic-embed-text (768-dim)

Process

embed_texts(chunks) → List[List[float]]
Batch processing for efficiency
COSINE distance metric

Routing

embeddings.py service
ENABLE_EMBEDDINGS env flag

Stage 8: Vector Upsert

Target Collections

asx_docs — ASX filing chunks
news_chunks — News article chunks
commentary_chunks — Memo chunks

Payload Contract

document_id (canonical UUID)
ticker
doc_class, doc_subtype
chunk_index
title

Key Rule

Point ID = {document_id}:{chunk_index}
UPSERT (not insert-only)
768-dim, COSINE — never change

Stage 9: RAG Query

Endpoint

POST /rag/query
source: asx_docs | news | commentary | hybrid
GET /api/context/ticker?ticker=XYZ

Process

Embed query text (same model as upsert)
Cosine search in Qdrant collection(s)
Apply ticker filter if specified
Return top_k scored hits

Returns

Chunk text + payload
Similarity score
Source metadata (ticker, doc, date)

Stage 10: Chat Response

Context Assembly

Recent chat history (limit 12)
Company dossier (limit 5)
Session summaries (limit 2)
Entity observations (limit 8)
Temporal anchor (current UTC date)

Agent Loop

Build system prompt with tools
Call LLM (local or backend-routed)
Parse: direct reply | tool call | action
Execute tool → feed result back
Repeat until final answer

Output

SSE stream: chunk | tool_call | done
Evidence sources listed
Action proposals (await /confirm)
Stored in StateStore chat_messages

Operations & Governance
System contract, active workstreams, and operational invariants
System Contract Invariants
1
Backend is sole authority
All data, extraction, RAG, and retrieval lives in the backend. Cockpit is a pure client — no direct Postgres or Qdrant access from Cockpit.
2
Pipeline layer ordering
Ingestion → Extraction → Storage → Retrieval → Analysis → Client. No layer skipping. No data shortcuts from client to storage.
3
Deterministic vector IDs
Point IDs = {document_id}:{chunk_index}. NEVER uuid4(). IDs must be reproducible from same input for upsert idempotency.
4
Single extraction authority
All extraction flows through multipass_extraction.py. No parallel extraction implementations. No bypasses.
5
Fail-fast principle
Surface ambiguity immediately. No silent fallbacks. No swallowed exceptions. No default returns that hide failure.
6
GPU process guard
Run gpu_process_guard.sh --check before spawning llama-server. Exit 1 = rogue process, Exit 2 = VRAM critical. Resolve before continuing.
7
No speculative features
Implement exactly what was asked. No future-proofing, no extra configurability, no abstractions for single-use code, no error handling for impossible conditions.
8
Milestone commits mandatory
Every confirmed-working state must be committed. Format: milestone(subsystem): what works. Working: / Tested: fields required. Never end session with uncommitted working state.
