Tenn Architecture Diagrams

Two diagrams, two answers.

Tenn has one architecture, but two useful ways to look at it. Use the runtime map when you care about deployed services and storage. Use the authority flow when you care about why the backend comes before the agent, how tool-calling interacts with infra, and where chat or memory features actually sit.

How to choose

The confusion came from mixing a deployment view with a control-flow view. The runtime map is about what runs. The authority flow is about who is allowed to do what.

Quick guide

  • “What services exist?” -> Runtime Topology
  • “Why is backend before agent?” -> Authority + Delegation Flow
  • “Show me one company’s actual data in the map” -> Ticker Map
  • “Where do writes happen?” -> Both, but especially Authority Flow
  • “What ports and storage exist?” -> Runtime Topology
  • “Where are chat history and memory features?” -> Both, now surfaced near the top
