Tenn Authority + Delegation Flow

This is the control-flow view of Tenn. It explains why the backend comes before the agent: backend APIs are the authority boundary, the agent is the orchestration runtime, and infra is the set of storage and execution resources used behind those boundaries.

What this view is for

Use this page when you want to understand tool-calling, backend authority, read-only versus mutating paths, and why infra is shown after the agent in the flow. This is not a deployment diagram; it is a responsibility diagram.

Key interpretation

  • Frontend asks the backend for authoritative data and actions.
  • Backend APIs own the contract and correctness boundary.
  • Agent runtime decides how to orchestrate tools within that boundary.
  • Infra provides storage, vector search, LLM inference, and async execution.

Chat features in this view

Chat here means SSE response streaming, tool invocation, approval-gated actions, verification prompts, and temporal anchoring in the agent loop.

Memory features in this view

Recent turns, dossier state, company memory, market memory, and commentary memo context are assembled before the model answers.

Why this matters

The backend still owns truth, but the chat layer decides how those context sources are combined into an answer or an action proposal.

Structured Financials

Multi-period extracted financial rows for one ticker: revenue, EBIT, NPAT, cash flow, and balance-sheet lines.

View surface: `GET /api/context/ticker` -> `asx_periodic_financials`

Filings + Announcements

ASX filings, announcement records, and written filing evidence that back the extracted financial truth.

View surface: documents + `asx_docs` + announcements bundle

News + Commentary

Written news context and commentary memos used for sentiment, catalysts, and narrative synthesis.

View surface: `news_chunks` + `commentary_chunks`

Dossier + Memory

Per-company notes, situations, prior findings, and market context that the agent can assemble into answers.

View surface: `company_memory`, `market_memory`, recent turns, dossier state

Frontend Surface (`cockpit-ui`)

UX Shell CockpitLayout, sidebar, status indicators, and the page-level frame operators use.
Feature Screens Chat, Operations, Verification, Intel Pulse, News, History, and Settings.
Client Integration `api-client.ts` provides REST, SSE streaming, stores, and job-stream hooks.

Backend Authority (`financial-engine_v2`)

FastAPI Surface `/api/cockpit/*`, `/api/context/*`, `/api/extraction-review/*`, and `POST /rag/query` define the authority contract.
Data Authority Backend owns ingestion, extraction, storage, retrieval, and correctness. Cockpit is a client, not an alternative source of truth.

Agent Orchestration

Agent Loop Runtime AgentLoop, ResponseParser, ToolExecutor, and ToolRouter coordinate reasoning and tool usage.
Chat + Memory Context Recent turns, dossier state, company_memory, market_memory, and commentary-derived evidence are assembled before the model answers.
Tool Surface Read-only tools gather context; mutating tools require confirmation and execute through controlled backend/runtime paths.

Infrastructure Resources

Storage Postgres for structured truth and Qdrant for vector search.
Execution llama.cpp for inference and Celery/Redis for async or mutating execution paths.

Read path

Operator -> frontend -> backend API -> context assembly -> agent loop -> read-only tools -> Qdrant, llama.cpp, or memory surfaces. Recent turns, dossier state, company memory, market memory, and commentary evidence are part of the assembled answer context.

Mutating path

When an action changes state, the agent does not write directly to core stores. It proposes or confirms the action, then routes execution through controlled runtime infrastructure such as Celery/Redis. Memory updates and dossier changes still happen through governed paths, with backend-owned storage remaining the source of truth.
