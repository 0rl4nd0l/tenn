# Chat Guard Canonical Review And CSL Live Smoke

## Objective

Review whether the backend chat evidence guard is integrated into the canonical checkout, then run a read-only CSL Cockpit chat smoke only if the route can be called without mutating chat history, Tenn memory, financial truth, Qdrant, news stores, runtime topology, model/GPU configuration, Docker, cron, or services.

## Scope

- Verify canonical branch, HEAD, dirty state, worktrees, registry state, and overlap status.
- Confirm backend and frontend evidence guard commits are ancestors of HEAD.
- Inspect guard source, tests, and UI/backend evidence-actionability mappings.
- Run focused existing compile, pytest, and ruff validation.
- Inspect runtime readiness without restarting or changing services.
- Identify the Cockpit UI chat endpoint from code/tests before any live call.
- Capture CSL smoke evidence only when a safe stateless/test route is available.

## Forbidden

- Do not edit backend, frontend, runtime, extraction, parser, memory, storage, Docker, cron, or service source/configuration.
- Do not write to production data stores, Tenn memory, Postgres, Qdrant, news SQLite files, canonical financial truth, or extraction outputs.
- Do not restart backend, frontend, Docker containers, systemd units, llama, Ollama, or GPU/model services.
- Do not install dependencies or run broad unrelated tests.
- Do not use old worktrees or external web data as Tenn evidence.
